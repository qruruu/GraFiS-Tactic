# Исправление окон и запросов сохранения трафаретов — версия 2

Эта версия добавляет исправление конкретного поведения со снимков: отдельные окна `.vss`, запрос сохранения «Моделирования» и попытка записать открытый только для чтения трафарет. Она включает предыдущие исправления обработки событий.

## Изменения в коде

1. Инициализация 32 трафаретов запускается только при активном редактируемом рисунке. При открытии отдельного `.vss` она ждёт события активации рисунка. Экспорт/обновление стилей, импорт мастеров и создание временных свойств дополнительно проверяют тип назначения.
2. Панели инструментов создаются один раз на экземпляр трафарета. Свойства/стили/мастера подготавливаются отдельно для каждого нового рисунка. Это исключает повторное создание кнопок при переключении документов.
3. Новый `c_GFSStencilSession` открывает уже загруженный трафарет через `visOpenRO + visOpenDocked` относительно активного рисунка. После проверки списка `DockedStencils` скрывается только отдельное MDI-окно трафарета (тип 2), а не панель фигур. В начале работы также обрабатываются видимые отдельные окна других уже загруженных read-only трафаретов.
4. Read-only трафарет, исходно открытый без несохранённых изменений, считается ресурсом библиотеки: его изменения в памяти, вызванные выполнением макросов, не требуют сохранения. Файл на диске не записывается и не перезаписывается. Рисунки и трафареты, намеренно открытые для редактирования (`ReadOnly=False`), не помечаются сохранёнными.
5. Закрытие проекта освобождает обработчики жизненного цикла. Открытие очередного рисунка в том же Visio повторно использует трафареты в панели фигур.

## Как применить

Это исходники и скрипт подготовки, **не готовые перепакованные `.vss`**. Загрузка `_codes` на GitHub не обновляет код внутри трафаретов.

Распакуйте архив и выполните на Windows с установленным Visio:

```powershell
.\tools\apply-visio-fixes.ps1 -SourceDirectory 'C:\папка-с-трафаретами' -OutputDirectory 'C:\GraFiS-fixed-v2'
```

Скрипт создаёт новую копию папки и меняет код только в копиях `.vss`. Он допускает проверенную исходную версию и модули первого пакета; другое содержимое будет отклонено до записи. Новые классы создаются как классы, вспомогательные модули — как стандартные модули. Существующие формы и классы сохраняют дизайнеры и свойства.

После компиляции и проверки копии трафареты нужно использовать из неё. Если старые схемы сохраняют абсолютный путь к старой библиотеке, они продолжат загружать старые `.vss`. Сначала сделайте резервную копию старой папки; после успешной проверки замените в ней соответствующие `.vss` на подготовленные копии, сохраняя имена файлов. Рабочие рисунки не заменяются. Применение требуется к библиотеке один раз, а не вручную к каждой схеме.

## Проверка

- В VBA выполните Debug → Compile для изменённых проектов. Runtime-проверка здесь не проводилась: в среде нет Windows/Visio.
- В одноразовый рисунок импортируйте `tests/GFS_StencilSessionTests.bas` и любой `c_GFSStencilSession.cls`; запустите `RunStencilSessionTests`. Тест проверяет два рисунка, docking, отсутствие запроса сохранения runtime-трафарета и сохранение признака несохранённых изменений в рисунках/редактируемых трафаретах. Он создаёт и удаляет только свой временный трафарет.
- Откройте два рабочих рисунка-копии. Трафареты должны быть доступны в панели «Фигуры», а отдельные окна `.vss` должны исчезнуть после активации рисунка. При закрытии не должно быть запроса записи read-only «Моделирования».
- Измените рабочую схему и закройте её: обычный запрос сохранения схемы **должен остаться**.
- Откройте копию трафарета для намеренного редактирования: её окно и запрос сохранения изменений **должны остаться**.

## Границы исправления

Нужен хотя бы один загруженный обновлённый трафарет с включёнными макросами. Код не сможет автоматически найти отсутствующую библиотеку, если все сохранённые пути не существуют. Открытие read-only `.vss` без какого-либо рисунка может кратковременно показать отдельное окно: оно будет подключено/скрыто после активации рисунка. Вопросы совместимости контролов/ссылок VBA и поведения docking в конкретной версии Visio требуют нативного теста. Не следует считать этот пакет проверенной бинарной сборкой до такой проверки.
